# Web Quality Skills Showcase Video Design

## Goal

Create a short `github_skills_showcase` capsule video for `addyosmani/web-quality-skills`.

The video should feel like a practical front-end release checklist, not generic AI tool promotion.

## Format

- Capsule: `github_skills_showcase`
- Route: short silent repo showcase
- Aspect ratio: 3:4
- Duration: 8-10 seconds
- Audio: packaged BGM only
- No voiceover
- No burned subtitles
- 4-5 visual cards

## Audience

Primary audience:

- Front-end developers preparing pages for release.
- Builders who already care about Lighthouse, Core Web Vitals, accessibility, and SEO.
- Coding-agent users who want better review checklists before changing code.

Wrong audience:

- Users expecting guaranteed ranking, guaranteed performance scores, or fully automated fixes without review.
- Users looking for scraping, traffic manipulation, account automation, or bypass behavior.

## Story Direction

Use the "before release, catch web quality issues early" angle.

Avoid phrasing like "AI efficiency tool", "AI empowerment", "automatic optimization", or broad "productivity artifact" language.

Preferred public wording style:

- Concrete page problems: slow first screen, awkward interaction, layout shift, missing labels, unclear search metadata.
- Concrete workflow: inspect first, make a checklist, then change code.
- Concrete scope: performance, Core Web Vitals, accessibility, SEO, best practices.

## Source Material

Use real, local screenshots derived from the repository:

- README content area showing the value proposition and available skills.
- `skills/` directory listing showing the six skills.
- Codex setup doc content showing installation/use instructions.
- One or more `SKILL.md` snippets only if needed to prove the workflow.

Screenshot rules:

- Crop out browser chrome, address bars, GitHub URL areas, sidebars, and visible domains.
- Do not show raw links, domains, QR codes, or visible link instructions.
- Do not use generated evidence cards unless real screenshots fail.

## Hard Compliance Rules

Visible public materials must not contain:

- URLs, domains, QR codes, or link prompts.
- The word `链接`.
- License claims such as `MIT` or `商用可用`.
- Internal production words such as draft, source, revision, v1, real asset, or similar handoff language.
- Claims that the tool guarantees ranking, performance scores, accessibility compliance, or security outcomes.

## Artifacts

Final output should land under a versioned release directory for this project and include:

- Final video in `public/`
- Cover in `public/` if generated by the capsule run
- Publishing copy in `public/`
- QA reports in `qa/`
- Internal value card, storyboard, and source notes in `internal/`
- Manifest pointing to current final artifacts
