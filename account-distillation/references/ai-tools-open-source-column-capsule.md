# AI Tools/Open-Source Column Capsule

Use this reference when turning AI工具, AI开源, GitHub, Agent, or office-automation benchmark posts into repeatable short-video account methods.

Source basis: the 20260609 Douyin deep run completed 18/18 S-tier posts with local MP4, SiliconFlow transcript, dense-frame visual review, keyframes, and final content-complete reports.

## Scope

Core account type: weak-personal-IP column accounts that repeatedly explain AI tools, open-source projects, GitHub repos, office workflows, AI video workflows, Agent/dev tools, or low-cost hardware/AI projects.

Exclude from core conclusions: AI变现/卖课/招商, lead-gen, ecommerce, short-drama traffic, generic AI news without demo translation, pure opinion/IP credibility, and posts where the main promise is financial outcome rather than tool understanding. Finance-adjacent tool posts may be retained only as risk-marked examples.

## Durable Lanes

1. **Tool List / AI神器榜单**
   - Promise: many tools saved in one post.
   - Proof: UI and output by second 5.
   - Loop: numbered card -> UI -> one action -> result -> friction note.
   - CTA: pinned tool list, prompt pack, install note.

2. **GitHub/Open-Source Radar**
   - Promise: a repo solves a concrete task or replaces a paid tool.
   - Proof: GitHub star/update/readme evidence plus run result, not star count alone.
   - Loop: repo proof -> demo/result -> who needs it -> install/caveat.
   - CTA: repo list, install notes, comparison table.

3. **AI Office Formula**
   - Promise: stop doing a familiar office task manually or incorrectly.
   - Proof: wrong result or before/after file transformation.
   - Loop: failed habit -> formula/prompt -> AI execution -> local edit -> final result.
   - CTA: worksheet, prompt formula, template file.

4. **AI Video Workflow Tutorial**
   - Promise: high-complexity effect becomes a repeatable workflow.
   - Proof: finished clip first, then toolchain.
   - Loop: case account/result -> prompt/script -> generation settings -> editing -> final playback.
   - CTA: prompt pack, settings list, project file.

5. **Agent/Dev/Hardware Project**
   - Promise: a low-cost or open project performs an unexpectedly advanced task.
   - Proof: physical demo, architecture, GitHub/doc, terminal, price screenshot, or UI state.
   - Loop: result/device first -> cost/proof -> architecture/doc -> live demo -> caveat.
   - CTA: parts list, repo, config checklist.

## Opening Rules

- First 0-3 seconds must show one of: finished result, failed output, GitHub proof, device/demo proof, tool UI, or concrete list title.
- Do not open with self-introduction, abstract AI news, or "今天给大家介绍".
- For tool/tutorial posts, show the result before explaining the tool.
- For open-source posts, combine authority proof with run proof before second 8.
- Put the most instantly visual proof first; save dense details for the body.

Reusable opening formulas:

- `{人群}别再手动做{任务}了，这个AI流程可以{具体结果}`
- `这个开源项目，能把{输入}直接变成{输出}`
- `{工具A}+{工具B}，把{复杂任务}拆成两步`
- `{付费/笨重工具}可以先停一下，这个开源方案已经能{能力}`
- `{硬件/Agent}居然只要{低成本}，就能跑{高级能力}`

## Visual Proof System

Use real evidence before stylized explanation:

- GitHub repo page: stars, README, release/update, docs, examples.
- UI/demo: input, operation, output, before/after.
- Office workflows: raw messy file, AI prompt/code, final file.
- Dev/hardware: device close-up, price screenshot, terminal/code/doc, runtime screen state.
- AI video: finished clip, prompt, generation parameters, edit timeline, final playback.

Common visual devices:

- high-contrast subtitles and short bottom captions
- red/yellow boxes, cursor/finger pointer, zooms on star counts/buttons/results
- dark-mode GitHub/terminal UI for technical credibility
- before/after hard cuts for tool value
- bento/grid cards for parameter or feature density
- final result replay to close the loop

## Script Skeleton

Use this default skeleton unless the source evidence suggests a stronger one:

1. **Proof Hook**: show result, repo, failure, or device immediately.
2. **Task Translation**: state the user task in plain language.
3. **Authority/Trust**: star count, open-source status, official model/tool name, or real test evidence.
4. **Demo Loop**: one concrete input/action/result sequence.
5. **Friction Removal**: free, local, one-click, template, install, or no-code note.
6. **Boundary**: limit, platform risk, config requirement, privacy, copyright, or finance disclaimer.
7. **Save/Comment CTA**: repo list, prompt pack, worksheet, parts list, or settings.

## Quality Gates

- Do not claim `content_complete` unless transcript, dense-frame visual evidence, and keyframe/opening audit all exist.
- Every reusable claim must cite a local final report, dense-frame review, or winner card.
- Do not copy creator scripts; abstract the sequence and proof mechanism.
- Verify free/open-source/local/privacy claims at publish time.
- Blur API keys, cookies, account names, private files, phone/email, and signed URLs.
- For finance, medical, legal, or security tools, include a boundary note and avoid outcome guarantees.
- If the video only has metadata/caption, mark it as screening material, not a reusable mechanism.

## Production Defaults

- Duration: 35-75 seconds.
- Aspect ratio: 9:16 for Douyin/TikTok/Bilibili shorts; adapt separately for video号 6:7.
- Subtitle density: short lines, one idea per cut.
- Evidence density: first proof by 5 seconds; at least three concrete proof shots per post.
- Ending: replay result or show final asset; do not end on abstract CTA only.
