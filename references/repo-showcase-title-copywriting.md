# Repo Showcase 标题与片内文案

## 先写最能打的

主标题先抢停留。标题党、强修辞、个人判断、反问和口语夸张都可以用。

`必看、必装、封神、王炸、炸裂、掀桌、打穿、裸奔、最好、最快、唯一、零成本、全自动、替代` 不是违禁词。别看到强词就自动改软。

一句话像不像人，比它有没有填满公式更重要。可以写第一人称，可以有脾气，也可以只说半句。别写 README 摘要、功能清单和公关稿。

## 七套口气

| 胶囊 | 主标题怎么说 |
| --- | --- |
| `repo_showcase` | 抓机制坑、返工和上生产前的判断 |
| `repo_show_bear` | 最锋利，直接说损失、风险和旧活该停了 |
| `repo_show_data` | 像亲手跑过，拿真实数字和结果说话 |
| `repo_show_leaf` | 极短，具体名词，允许不完整短句 |
| `repo_show_lin` | 像编辑下判断，有偏好，不写公关话 |
| `repo_signal_grid` | 第一行说人话判断，第二行补普通项目类型 |
| `repo_showcase_compare` | 放大选择焦虑，像一张一秒大字报 |

每套的 `recipes/copy.md` 都有自己的“人话钩子底稿”。那是口气参考，不是填空模板。

## 最后只查一次

只有下面四类问题阻断发布：

1. 标题跟内容无关，或明显靠骗点把人引进来。
2. 捏造数字、测试、案例、结果、权威或官方身份。
3. 故意不兑现答案，或者引导观众去下集、私信、二维码、站外才能拿到答案。
4. 违法、作弊、欺诈、危险用途，或无资质的医疗、金融、法律等受监管承诺。

强词本身不触发拦截。包装比内容更猛一点也能发，只要内容确实接得住核心意思。

不违规就能发，其他交给编辑判断。
