# Motion

## State Machine

标准 18 秒版规划 6–9 次有语义的状态变化：

1. 小白与 `project_pain` 对应的问题场景、待处理对象或压力来源同帧出现，第 0.00 秒开口。
2. 硬切专家说明"这个开源项目"的解决方案。
3. 官方结果或 Demo 在第 5 秒前完整出现。
4. 两至三个 `advantage_points` 依次用动作和结果证明。
5. 官方仓库身份或一次可信信号清晰落版。
6. 小白一次追问，专家用结果完成回答和交付。

12 秒版可合并第 4、5 状态；25 秒版可为每个优势点增加一个结果保持或局部放大，但总状态仍不超过 9 个。状态变化始终服务于问题、方案、证据和交付，不把具体项目名或输出格式设为固定画面。

## Editing Rhythm

- 痛点拍允许动作未完成或压力瞬间作为 cold open；不从静止正脸口播开始。
- 角色切换用硬切、动作匹配或前景遮挡，转场长度不应吞掉信息。装饰性炫技转场不计为状态变化。
- 各优势点的证据镜头采用相似时长、相似机位或相似画面区域，节奏上形成可预期的推进感。
- 第一个真实结果最迟在第 5 秒完全可读。若生成视频无法稳定展示结果，改用本地合成、定格对比或可验证素材，不得只靠台词声称成功。
- 可信信号只做一次清晰聚光，可以短暂提高切速和音效密度，但必须在 2–4 个画面内收束，不变成蒙太奇噪音。
- 最后一秒必须看到交付动作已经发生，不使用长 Logo 尾卡、纯关注 CTA 或冻结表情替代结果。

## Digital Human

- 默认使用 H3 原生语音与口型同步；只有显式选择外部 TTS 时，才先生成单条批准音频，再把它与对应单张参考板交给 AutoDL.Art H3。两条路线都不额外调用独立口型工具，也不在 H3 输出后重新配音。
- 口型镜头优先中近景、脸部无遮挡、头部转动克制。证据镜头可用画外音，减少每一拍都强制对口型造成的身份漂移。
- 动作生成前加载同一人物锚点和对应角色参考图。发现脸型、年龄、肤色或五官漂移时，单独重做该镜头，不继续批量扩散错误。

## Project Evidence Motion

本变体优先使用真实屏幕视频：GitHub 段采用真实浏览器滚动录屏，WorkBuddy 段采用原生 OBS 窗口录屏。两段素材都以原速或轻微裁尾进入，不能用截图补帧伪装成录屏；WorkBuddy raw 必须留存，edited 仅为可选派生物。

- 屏幕证据采用“上下文 → 重点”两段式：先让观众看懂页面/窗口属于什么，再对本期主张对应的事实区域做一次局部推近。每条录屏最多一次重点推近，保留原生页面运动逻辑，不添加假 UI 或装饰性鼠标轨迹。

- 真实网页、README 和 Demo 必须先由真实来源采集。默认采用真实抓取优先路线：真实 GitHub 页面截图与滚动录屏直接作为证据画面；api.github.com 官方原始素材（raw SVG、GFM 渲染 README 表格）次之；确实无法抓取时才在 H3 人物镜头之后由本地后期合成，使用无描边蓝黑金网格模板，动效用整段滑入、跳切或平滑推近后稳定停留。只有显式选择 `h3_reference_board` 时，才把素材与人物资产组成单张参考板交给 H3 生成拿取、展示或翻动；两条路线不得在同一段重复叠加。
- 参考板路线中的素材只保留一个主证据区，禁止塞入网页长图、多个并列小图、操作提示或密集标注。渠道输入过大时优先裁切事实区域并压缩，而不是降低人物参考清晰度。
- 结果前后对比尽量同屏或硬切匹配，先看结果再解释机制。
- Stars、更新时间等可信证据只做一次清晰聚光，不用重复闪烁放大。
- 机制画面按本期 `mechanism_steps` 提供的 `输入 -> 处理 -> 输出` 依次点亮；只有实际使用自制机制图时才显示"结构示意"。不得把某个项目的文件格式、页面数量或处理步骤写成胶囊默认内容。`clean_title_only` 下直接使用真实仓库和官方 Demo 素材，不添加解释性标签。
- 不要求人物精准指向网页细小元素；让人物自然拿起、展示或翻动素材即可。运动使用完整滑入、跳切、平滑推近和稳定停留，禁止连续小步平移、微抖或碎步缩放。
- 比例与画布不一致的素材用整段定向下滑或横移展示：过高图宽度对齐后从上往下滑，过宽图高度对齐后从左往右平滑横移（smoothstep 速度曲线），移动范围一次走完；不用模糊放大垫底，也不用缩小素材留大白边。
