# Structure

## Core Dramatic Unit

- 一个主题先生成机制不同的创意候选，再选择一条生产；不得先套固定动物剧情、最后只换Logo。
- 基础生成单元仍是一个 `5-10s` 的“失落低成本3D动画名场面”，但默认完整成片不是单个单元。宣传故事默认由两个单元组成，约 `12-18s`。
- 最强的默认结构是：`<具体困境> -> <主角尝试并失败> -> <带哭腔绵长喊妈妈——> -> <另一个角色有力喊X来！> -> <救场角色只做一个动作解决> -> <同一救场角色说一句广告语> -> <本地信息/证据卡>`。
- `X来` 不是可以任意替换的口头禅。X、登场救场主角、解决能力和宣传对象必须闭环：`<宣传对象> -> <可视觉化的X> -> <X实体化救场主角> -> <X特有动作解决> -> <同一对象广告语>`。
- 当X是动物时，救场主角必须就是该动物，例如“马来”由马登场、“猫来”由猫登场。当X是商品或物件时，优先让商品/物件拟人化，例如“书来”由拟人书本登场；仅用“猫头鹰象征知识”这类间接联想不够。
- 角色层级固定：哭喊“妈妈——”的是 `problem_character`，负责制造代入和困境；喊“X来”、登场、解决并说广告语的是 `xlai_responder`，它才是封面、高潮和宣传记忆中的核心主角。两者必须是不同个体，但默认共享X身份，例如小书与大书，而不是山羊与书。
- 全片角色替换测试：把任一可见角色换成与X无关的动物、人或物件后，如果观众会先记住该无关角色，则候选不合格。`书来`默认全员是书，`羊来`默认全员是羊；只有用户明确要求跨物种配角时才可例外并记录理由。
- 单场事故型也可使用：`<正常动作预期> -> <身体以略错方式执行> -> <角色严肃承受后果>`，但不能用抽象哲理对白代替登场和结果。
- 每个单元只保留一个主视觉事故。动作完全正常会失去记忆点；随机肢解、穿模或不可辨认的崩坏也不合格。
- 首帧必须已经出现怪角色、困境或不合理姿势；前 `1.5s` 让困境可读，随后用一次失败动作给哭喊建立原因。“妈妈——”之后停顿 `0.2-0.8s`，再由另一个角色喊 `X来！`；解决动作最迟在成片前 `8s` 启动。
- 对白默认是咒语式角色名、求援词或极短回应，不优先写完整问答和哲理金句。

## Summon And Payoff Beats

1. `怪相`：第一帧近景或全身景就让角色/困境可辨认，不先交代背景。
2. `受阻`：用一个动作和一个接触声证明事情办不成，主角因此失去镇定。
3. `求援`：弱势角色以不可识别、带哭腔的合成声音绵长喊“妈妈——”。
4. `回应`：短停顿后，由另一个救场角色以明显不同的有力声音喊出原创 `X来` 名称。
5. `登场`：硬切、快速推镜、烟雾或重物落地揭示X的实体化主角；物种、物体轮廓、服装或关键道具必须让X不依赖字幕也可辨认。
6. `见效`：来者用X或宣传对象特有的一个动作立即改变局面；把角色换成无关对象后动作若仍完全成立，主题绑定过弱。
7. `广告语`：救场角色面对结果或镜头说一句与主题因果相连的短广告语，不背卖点清单。
8. `定格`：用严肃正面姿势、荒诞环境和必要的本地信息卡收尾，不解释笑点。

## Promotional Architectures

- `summon_solution`：问题、失败、哭腔“妈妈——”、第二角色喊“X来”、立即结果、广告语、信息卡。
- `self_awakening`：对立、失败、哭腔“妈妈——”、导师/同伴喊“X来”、主角在帮助下反转、广告语、主题卡。
- `visual_pun`：怪文字/物件、错误理解、哭腔“妈妈——”、揭示者喊“X来”、环境答案、广告语。
- `conflict_proof`：对立、可见落败、哭腔“妈妈——”、第二角色喊“X来”、动作胜负、广告语、用户证据卡。
- 宣传信息必须参与因果：主题对象解决了什么、改变了什么或证明了什么。仅在无关剧情后贴Logo不算主题变体。
- 语义替换测试：若把“X来”换成任意其他词、把救场主角换成任意动物，剧情仍无需修改就成立，则该候选不合格。

## Five-Beat Fable

规划 `11-300s` 长视频时，用以下五拍扩写；短视频可以只取其中最强的一拍：

1. `预兆`：主角面对一个极小、具体、可拍的障碍。
2. `尝试`：主角以符合动物预期、但身体实现略错的方式行动。
3. `见证`：第二角色提出直接而严肃的问题，不负责吐槽。
4. `代价`：动作事故造成小而明确的后果，主题被抬升。
5. `余味`：角色作出朴素决定或留下一句过大的判断，不解释笑点。

## Duration Architecture

- 每个分镜持续 `5-10s`，默认 `8s`；任何单次云端视频请求不得超过 `10s`。
- `5-10s`：一个 Agnes 文生视频单元，或一张 Agnes 文生图加本地静态持镜/极轻推镜。
- `11-300s`：按语义拆成多个独立单元。只有动作、地点、叙事阶段或主要视点发生真实变化时才切镜。
- 长片默认使用混合路线：关键动作场景用 Agnes 视频，其余建立、见证、余味场景用 Agnes 图片加本地轻运动，降低免费层视频调用量。
- 不把多个 Agnes 请求假装成一个连续长镜头。跨镜角色只依赖文本锚点软锁定，剪辑点应容纳外形和空间细节的轻微变化。
- 每次先做最难、最代表风格的一场；首镜未通过，不批量生成后续场景。

## Scene Plan Contract

每个场景至少记录：

- `id`、`duration_seconds`、`media_mode`。
- `story_beat`、`normal_action_expectation`、`single_body_anomaly`、`visible_consequence`。
- `character_anchor`：逐字复用的完整角色外观锚点。
- `visual_action`、`camera`、`video_prompt` 和可选 `dialogue`。
- `continuity_boundary`：本镜必须保持的状态，以及允许在硬切处变化的状态。
- `frames`：Agnes 视频固定 `24fps`，整秒目标按 `duration_seconds * 24 + 1` 计算并满足 `8n+1`，本胶囊范围 `121-241`；多出的 1 帧是提供商约束。
- `theme_connection`、`proof_payload`、`local_text_plan`：宣传主题如何进入剧情、需要哪些证据、哪些文字由本地渲染。

## Failure Patterns

- 一段塞入多个事故、多个主题或连续复杂动作。
- 用标题解释笑点，画面本身却不可读。
- 角色知道自己在拍网络梗，主动挤眉弄眼或说流行语。
- 用大量快切掩盖动作生成失败。
- 为追求“粗糙”而添加随机故障、VHS、雪花或强烈 glitch。
- 把 `X来` 写成长篇自然对话、情感独白或哲理问答，导致名字不再像召唤口令。
- 只做动物怪步态却没有呼唤、登场或可见结果，观众无法在前几秒识别系列机制。
